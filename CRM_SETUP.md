# Заявки и CRM: Tally → Airtable

Сайт уже умеет принимать ссылки вида `?ref=slug`, хранить первый и последний подтверждённый реферальный переход 30 дней и передавать атрибуцию в Tally. Tally embed появляется только после настройки `VITE_TALLY_FORM_ID`; до этого посетитель видит рабочий контакт Натальи в Telegram.

## 1. Форма Tally

Создайте и опубликуйте форму `Заявка · BULGARIA 2026` со следующими видимыми вопросами:

| Вопрос | Тип Tally | Обязательное |
| --- | --- | --- |
| Имя | Short answer | да |
| Telegram | Short answer | да |
| Телефон | Phone number | нет |
| Email | Email | нет |
| Страна | Short answer | нет |
| Формат участия | Multiple choice | да |
| Участников | Number | для полного пакета |
| Комментарий | Long answer | нет |
| Согласие на обработку данных для ответа на заявку | Checkbox | да |

Варианты `Формат участия` должны совпадать с Airtable:

- `Форум · 25 €`
- `Полный пакет · 1 человек`
- `Полный пакет · 2 человека`
- `Полный пакет · 3 человека`
- `Самопрезентация`
- `Ещё выбирает`

До запуска добавьте ссылку на реальную политику конфиденциальности. Согласие на рекламную рассылку, если она понадобится, сделайте отдельным необязательным checkbox — не объединяйте его с обработкой заявки.

## 2. Скрытые поля Tally

Добавьте через `/hidden` поля с точными именами ниже. Имена чувствительны к регистру:

```text
lead_source
ref_first
ref_last
credited_ref
utm_source_first
utm_source_last
utm_medium_first
utm_medium_last
utm_campaign_first
utm_campaign_last
utm_content_first
utm_content_last
utm_term_first
utm_term_last
landing_first
landing_last
touch_at_first
touch_at_last
current_path
```

`credited_ref` — основной эксперт для зачёта: сайт передаёт `ref_first`, а если первого значения нет — `ref_last`. Комиссию имеет смысл считать только по заявкам со статусом оплаты `Оплачено`.

## 3. Подключение Airtable

В опубликованной форме откройте **Integrations → Airtable → Connect**, разрешите доступ к базе `BULGARIA 2026 · Заявки` и выберите таблицу `Заявки`. Сопоставьте видимые вопросы с одноимёнными русскими полями, а hidden fields — с полями с теми же английскими именами.

До подключения откройте настройки полей Airtable и задайте значения по умолчанию для всех новых записей:

- `Статус` → `Новая`;
- `Статус оплаты` → `Не выставлено`;

Для `Дата заявки` настройте Airtable automation на момент создания записи либо замените поле на системное `Created time`. Это поле не нужно сопоставлять с ответом посетителя.

У Tally есть журнал синхронизации рядом с интеграцией. После настройки обязательно отправьте одну тестовую заявку по реферальной ссылке и убедитесь, что `ref_first`, `ref_last` и `credited_ref` появились в Airtable.

Официальные инструкции: [Tally → Airtable](https://tally.so/help/airtable-integration), [hidden fields](https://tally.so/help/hidden-fields), [Tally embed](https://developers.tally.so/widgets/embeds).

## 4. Подключение формы к сайту

Скопируйте ID из адреса формы `https://tally.so/r/FORM_ID`.

Для локального запуска создайте игнорируемый Git файл `.env.local`:

```env
VITE_TALLY_FORM_ID=FORM_ID
```

Для GitHub Pages создайте repository variable `TALLY_FORM_ID`. Workflow `.github/workflows/pages.yml` уже передаёт её в Vite. ID формы публичный по своей природе и не является API-ключом.

## 5. Реферальные ссылки экспертов

После публикации сайта выполните:

```bash
npm run referrals -- https://username.github.io/repository/
```

Команда выдаст отдельную ссылку для каждого из девяти профилей на странице. Допустимы только заранее зарегистрированные slug, поэтому случайное или подменённое значение не попадёт в CRM.

Ограничение статической схемы: посетитель может очистить хранилище, открыть ссылку на другом устройстве или вручную изменить URL. Для текущей ручной сверки заявок и оплат этого достаточно; для юридически спорных комиссий позднее нужен серверный токен и привязка к платёжной транзакции.
