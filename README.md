# Business & Travel Bulgaria 2026

Одностраничный статический лендинг в направлении «Черноморский модернистский атлас». Проект собран на React и Vite и подготовлен для размещения на GitHub Pages.

## Маршрут и структура

В сборке две статические страницы: форум 12 сентября (`/index.html`) и Business Networking 6 сентября (`/breakfast.html`). Обе используют одну визуальную систему, одну форму заявки и один Worker.

## Локальный запуск

```bash
npm install
npm run dev
```

Production-сборка:

```bash
npm run build
npm run preview
```

Vite использует относительный `base: './'`, поэтому страница и локальные изображения работают внутри подпапки репозитория GitHub Pages.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите проект в ветку `main`.
2. В настройках репозитория откройте **Settings → Pages**.
3. В поле **Source** выберите **GitHub Actions**.
4. Workflow `.github/workflows/pages.yml` соберёт каталог `dist` и опубликует сайт.

Для ручной проверки перед push выполните `npm run check`.

## Форматы участия

- **Business Networking:** 6 сентября 2026 года, тренинг, завтрак и нетворкинг-сессия — **бесплатно по персональному приглашению**.
- **Только форум:** 12 сентября 2026 года, участие и кофе-брейк — **25 €**.
- **Полный пакет с отелем:** 8–13 сентября 2026 года — **500 €** для одного участника, **700 €** для двоих или **800 €** для троих. Перелёт и трансфер не входят в стоимость.

Коды форматов для CRM перечислены в `CRM_SETUP.md`. Перед публикацией страницы Business Networking два новых варианта нужно добавить в single select `Формат участия` в Airtable: Worker пишет записи без `typecast`, поэтому неизвестный вариант будет отклонён.

## Визуальная система

Основное направление — редакционный Atlas: холодная минеральная палитра, кобальтовые акценты, документальные фотографии, резкая сетка и контрастные типографические полосы. Локально подключены:

- `Sofia Sans Condensed Variable` — крупные заголовки;
- `Manrope Variable` — текст, навигация, метки и интерфейсные элементы.

## Заявки, реферальные ссылки и CRM

Все основные CTA ведут к организатору:

- Наталья Маслова;
- Telegram: `@maslovanataly` — `https://t.me/maslovanataly`.

В финальном contact-блоке всегда доступна нативная форма: имя, Telegram, дополнительный контакт, страна, формат участия, комментарий и согласие на обработку заявки. При валидном `VITE_LEAD_ENDPOINT` она отправляет JSON-заявку в Cloudflare Worker, а Worker записывает только разрешённые поля в Airtable.

Если endpoint не задан или не проходит проверку, отправка открывает заполненную заявку в Telegram `@maslovanataly`; посетителю остаётся нажать «Отправить». При блокировке нового окна форма показывает обычную ссылку на тот же заполненный текст. При сетевой ошибке или таймауте данные остаются в полях, и Telegram также доступен как fallback.

Для локальной проверки создайте `.env.local`:

```env
VITE_LEAD_ENDPOINT=https://your-worker.example.workers.dev/api/leads
VITE_TURNSTILE_SITE_KEY=your_public_site_key
```

`VITE_LEAD_ENDPOINT` — публичный адрес API, который Vite встраивает в клиентскую сборку. Airtable token и другие секреты должны храниться только в Cloudflare Worker Secrets; не добавляйте их в `.env.local`, GitHub Pages variables или переменные с префиксом `VITE_`.

Для GitHub Pages создайте repository variables `LEAD_ENDPOINT` и, после настройки Turnstile, `TURNSTILE_SITE_KEY`: workflow уже передаёт их в Vite-сборку. Worker находится в `worker/src/index.js`, его конфигурация — в `wrangler.jsonc`; секреты добавляются только через `npx wrangler secret put …`. До фактического деплоя Worker и добавления `LEAD_ENDPOINT` production-сборка безопасно остаётся на Telegram-fallback.

Реферальная ссылка имеет вид `?ref=slug`. Сайт хранит только проверенные first/last-touch значения 30 дней; зачёт и видимое имя получает последняя валидная реферальная ссылка, а первый переход сохраняется для истории. Имя, контакты и комментарий в `localStorage` не записываются. Сгенерировать все ссылки после публикации:

```bash
npm run referrals -- https://www.bulgaria2026.com/
npm run referrals -- https://www.bulgaria2026.com/breakfast.html
```

После `.html` не нужен `/`: правильный вид — `breakfast.html?ref=slug`. Генератор также исправляет случайно переданный адрес `breakfast.html/`, а опубликованный `404.html` восстанавливает уже разосланные ссылки такого вида без потери UTM-параметров.

Полная схема формы и подключения к Airtable описана в `CRM_SETUP.md`.
